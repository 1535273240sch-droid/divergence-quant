# 云服务器部署说明（唯一权威入口）

> **这篇文章回答一个问题：这么多东西，到底哪个是部署到云服务器上的？**
>
> 结论：**只有 `main` 分支的 Python 后端 + `web/ice-console` 静态控制台**是云服务器版本。
> 桌面 EXE、Docker 全栈、桌面启动脚本 **都不是** 云服务器部署内容。

---

## 一、按部署目标分类（重要）

| 产物 | 用途 | 是否部署到云服务器 |
|---|---|---|
| `src/dquant/` + `web/ice-console/` | Python 后端 + 静态控制台 | ✅ **是，唯一答案** |
| `desktop_app.py` / `DivergenceQuant.spec` / `build_desktop_exe.py` | Windows 桌面 EXE（PySide6） | ❌ 否，只给 Windows 本机用 |
| `.github/workflows/build-desktop.yml` | 自动构建 Windows EXE | ❌ 否，产出的是桌面安装包 |
| `docker-compose.yml` + `Dockerfile` | 8 服务全栈编排 | ❌ 否，**从未实机验证**，且代码实际只用 SQLite |
| `start_desktop.bat` / `*.vbs` | Windows 本地启动脚本 | ❌ 否 |

一句话记法：**服务器要的是 `src/` 和 `web/`，不是 `.exe`，也不是 `docker-compose`。**

---

## 二、权威版本标识

| 项 | 值 |
|---|---|
| 分支 | `main` |
| 版本标记 | git tag `cloud-server`（始终指向最新可部署到云服务器的提交） |
| 前端主题 | 冰透银白（默认），可选纯黑 |
| 数据存储 | SQLite（`data/engine.db`），不需要 PostgreSQL / Redis |

> ⚠️ **不要在服务器上用 scp/压缩包覆盖部署。**
> 那会导致服务器上的代码没有 git 记录，永远停留在拷贝那天的版本——这就是"每次部署都是旧版本"的根因。

---

## 三、部署步骤（最小化路径，已实测）

```bash
# 1. 拉取代码（首次）
cd /home/ubuntu
git clone https://github.com/1535273240sch-droid/divergence-quant.git
cd divergence-quant

# 2. 创建虚拟环境并安装依赖
python3 -m venv .venv
. .venv/bin/activate
pip install -e . -i https://pypi.tuna.tsinghua.edu.cn/simple

# 3. 配置（密钥可选，纯公开行情不需要）
cp .env.example .env

# 4. 常驻运行主引擎（后台）
nohup .venv/bin/python -m dquant.scheduler.engine \
  --source okx --interval 30 --db data/engine.db > logs/engine.log 2>&1 &

# 5. 启动 Web 控制台 API（可选）
nohup .venv/bin/python -m uvicorn dquant.api.main:app \
  --host 127.0.0.1 --port 8000 > logs/api.log 2>&1 &
```

后续更新版本：

```bash
cd /home/ubuntu/divergence-quant
git pull origin main        # ← 只有这一种更新方式
# 重启引擎和 API
```

## 四、前端主题说明

`web/ice-console` 默认即为 **冰透银白（Ice-Clear Silver-White）** 玻璃质感主题：

- 画布底色 `--canvas-1: #ece5d9`（暖白偏银）
- 纯黑「战情」主题为**可选**，通过右上角主题按钮切换，不再作为默认
- 若浏览器仍显示黑色，是旧的 `cq.theme` 缓存；本次已改用 `cq.theme.v2` 存储键，会自动回到冰透银白

---

## 五、安全红线

1. `LIVE_TRADING_CONFIRM` 必须保持 `NO`；引擎默认 dry-run，不要加 `--execute`
2. `data/okx-credentials.enc` 属于敏感文件，权限设为仅运行用户可读，禁止提交
3. `.env` 永不入库（已在 `.gitignore` 中）
4. 服务器只监听 `127.0.0.1:8000`，对外统一走 nginx 反代
